# treenity — детальный план разработки

**Русский** | [English](../eng/treenity-plan.md)

> Версия документа: 2.0 (по итогам реализации v0.1.0).
> Статус: ядро, симулятор и тесты реализованы и проходят; впереди — аппаратный
> порт, безопасность и масштабирование.

---

## 1. Задача

Библиотека строит mesh-сеть вокруг одного корневого узла **Master**.
Требования:

1. Сеть строится вокруг одного Master.
2. Полная абстракция от микроконтроллеров; лёгкая портируемость через
   пользовательский порт (API + колбэки).
3. Главный критерий — **бесшовное перестроение** топологии ради лучшего
   качества связи.
4. При приёме пакета из пользовательской прослойки библиотека получает пакет
   вместе с **RSSI и SNR** отправителя; значения используются для оценки связи и
   доступны наружу.
5. Транспорт — LoRa, но библиотека не привязана к модему.

## 2. Принятые решения

| Вопрос | Решение | Обоснование |
|---|---|---|
| Язык ядра | **C99** | максимальная портируемость, минимальный рантайм |
| Память | **только статика**, без `malloc` | предсказуемость на MCU |
| Масштаб | 100–1000 узлов на Master | влияет на размеры таблиц |
| Симулятор | **обязателен** | без него mesh-логику не протестировать |
| Безопасность | hooks, реализация позже | не блокирует v1 |
| Топология | **DODAG с корнем Master** | стандарт RPL для сетей с корнем |
| Метрика | композитная: **ETX + SNR** | ETX лучше hop-count; SNR информативен на LoRa |
| Broadcast | **managed flooding** с SNR-приоритетом | как в Meshtastic |
| Порт | структура указателей на функции | Contiki-NG NETSTACK, RadioHead |
| Служебный трафик | **Trickle** | адаптивный интервал beacon-ов |

Источники: RPL (RFC 6550), Trickle (RFC 6206), ETX (MIT), Meshtastic
mesh-algo, Contiki-NG NETSTACK, Semtech AN1200.13 (время в эфире).

## 3. Архитектура (реализовано)

Слои (снизу вверх): **PORT → Core → MAC → Link → Routing → API**.

- **PORT** (`include/treenet/port.h`) — реализует пользователь:
  `tx`, `now_ms`, `rnd` обязательны; `channel_free`, `log`,
  `timer_arm` опциональны. Приём — `treenet_rx(buf,len,rssi,snr)`.
- **Core** (`src/core`): ring-buffer приёма, таймеры, EWMA, утилиты, контекст.
- **MAC** (`src/mac`): кодек кадра, dup-cache, CSMA/CA, фрагментация, время в
  эфире.
- **Link** (`src/link`): beaconing (Trickle), таблица соседей, LQI.
- **Routing** (`src/routing`): DODAG, Rank, целевая функция, выбор родителя,
  DAO, таблица маршрутов вниз.
- **API** (`src/api/treenet.c`): жизненный цикл, poll, приём, пересылка, API.

Подробности — в [architecture.md](architecture.md) и [protocol.md](protocol.md).

## 5. Ключевые алгоритмы (реализовано)

1. **Rank** = `parent.rank + TREENET_RANK_STEP + link_cost(parent)`; строгий рост
   исключает петли.
2. **Целевая функция** `link_cost = (W_SNR·snr_score + W_ETX·etx_pen)/256`;
   ETX доминирует, поэтому качественный многошаговый путь выигрывает у одного
   плохого линка.
3. **Выбор родителя** по минимуму `candidate_rank`; **гистерезис** (25 %) и
   **dwell-time** (10 с) против флаппинга.
4. **LQI**: EWMA RSSI/SNR; PDR по beacon-ам с учётом объявленного интервала;
   ETX = 1/PDR.
5. **Beaconing (Trickle)**: интервал 3→12 с, случайное смещение, сброс при
   смене родителя.
6. **DAO**: надёжное (WANT_ACK) распространение маршрутов вверх до Master;
   таблица маршрутов вниз (storing mode).
7. **Managed flooding**: задержка ретрансляции тем меньше, чем ниже SNR;
   REPEATER — вне очереди.
8. **Hop-by-hop ACK** и ретрансляции для надёжных кадров.
9. **Фрагментация/сборка** датаграмм > MTU.
10. **Контроль целостности** — CRC-16/CCITT-FALSE (трейлер кадра, по умолчанию
    включён); семантическая валидация кадров; повреждённый кадр никогда не
    меняет состояние.
11. **Tickless-планирование** — периодические процессы (истечение маршрутов,
    старение соседей, сборка, DAO-refresh, PROBE) выражены вычисляемыми
    дедлайнами; в конце `treenet_poll()` порт получает ближайший дедлайн через
    `port.timer_arm()` для сна MCU.
12. **Роль «лист»** — конечное устройство, которое отправляет/принимает свои
    данные, но не пересылает чужой трафик, не ретранслирует flooding и не может
    быть родителем (флаг `TN_BEACON_ROUTER`).
13. **Быстрый ремонт по ACK** — next hop, не подтверждающий надёжные кадры,
    помечается «подозрительным» и исключается из выбора родителя; родитель
    перевыбирается немедленно (за секунды, а не за `PARENT_TIMEOUT`).

## 6. Верификация (текущая)

- **1918 проверок**, 0 провалов (`make test`, `ctest`).
- Сценарии: формирование сети, порядок Rank, unicast вниз/вверх, broadcast,
  бесшовное перестроение при отказе ретранслятора, сброс интервала beacon при
  смене родителя, устойчивость к битовым ошибкам, метрики соседей.
- **Corruption-тесты:** CRC ловит любой одиночный бит и усечение; повреждённые
  и семантически битые кадры (beacon/DAO/фрагменты) не меняют состояние;
  чужой `net_id` игнорируется.
- **Fuzzing** — мутационный (от корпуса валидных кадров) + случайный ввод,
  300 000 итераций без падений и нарушений инвариантов.
- **Стресс-тесты конкурентности** (`make stress`): ринг (1 млн записей, 1
  производитель / 1 потребитель) и библиотека (`treenet_rx` в одном потоке,
  `treenet_poll` в другом) — без потерь и порчи.
- Сборка без предупреждений с `-Wall -Wextra`.
- Пример: сеть Master + 5 узлов на ~1 км, Rank 0/8/16/24/32/40, unicast в обе
  стороны и broadcast доставляются.

## 8. Что осталось (roadmap)

### Фаза 9. Аппаратный эталонный порт (не начата)
- Порт под SX1262 + ESP32/STM32: `tx`, CAD, IRQ-приём с RSSI/SNR, время.
- Демо-прошивка: Master на шлюзе + узлы.
- Полевые испытания: PDR, задержка, конвергенция, дальность.
- Калибровка модели симулятора по реальным замерам.

### Фаза 10. Масштаб > 500 узлов (не начата)
- Non-storing mode: source routing от Master, O(1) память на узле.
- Оптимизация служебного трафика (Trickle `k`, подавление избыточных DAO).
- Разделение таблиц: маршруты только у Master/релевантных предков.

### Фаза 11. Безопасность (не начата)
- Заголовок `sec` + `TN_FLAG_SEC` уже заложены.
- AES-CCM/ChaCha20-Poly1305, управление ключами, защита от replay.
- Хэш канала (как в Meshtastic) для разделения сетей.

### Фаза 12. Энергосбережение (не начата)
- Sleep-циклы с длинной преамбулой, синхронизация окон приёма.
- Учёт duty-cycle в MAC (бюджет времени в эфире уже считается).
- Питание от батарей: адаптация интервалов по остаточной энергии.

### Фаза 13. Дополнительно
- Channel hopping / частотные планы.
- Приоритезация трафика и QoS.
- Multi-master / border router.
- Диагностический протокол (сбор топологии и метрик).

## 9. Риски и меры

| Риск | Мера |
|---|---|
| Флаппинг маршрутов | гистерезис + dwell-time; согласованные таймауты |
| Потеря маршрутов на зашумлённом канале | DAO надёжные (WANT_ACK) |
| Duty-cycle LoRa | учёт времени в эфире; Trickle; `FLOOD_CW` |
| Рост source-route / таблиц | limit по `MAX_ROUTES`; non-storing в будущем |
| Небезопасный RX-путь | `treenet_rx` только копирует; критические секции |
| Достоверность симулятора | калибровка по полевым данным |

## 10. Критерии успеха

| Метрика | Цель | Текущее |

| Служебный трафик | < 5 % airtime | `beacons_tx`/`airtime_ms` |
| Конвергенция после отказа | секунды, без флаппинга | подтверждено тестом |
| RAM на узел | в бюджете, 0 malloc | ✅ |
| Воспроизводимость симулятора | по seed | ✅ |
