# Тестирование

**Русский** | [English](../eng/testing.md)

## 1. Сборка и запуск

### CMake (рекомендуется)

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Цели:

- `treenet` — ядро библиотеки;
- `treenet_sim` — симулятор;
- `treenet_tests` — юнит- и сценарные тесты;
- `treenet_fuzz` — fuzzing парсера и пути приёма;
- `treenet_example` — пример.

### Make

```sh
make test      # собрать и запустить тесты
make example   # собрать пример
make run       # собрать и запустить пример
make fuzz      # fuzzing (200000 итераций)
make repeaters # отчёт: 1 Master + 30 повторителей (стресс-сценарии)
make stress    # многопоточные тесты конкурентности (ринга и библиотеки)
```

### Кросс-сборка под ARM

```sh
cmake -S . -B build-arm -DCMAKE_C_COMPILER=arm-none-eabi-gcc
cmake --build build-arm
```

Ядро зависит только от `stdint.h`/`stddef.h`/`stdbool.h`/`string.h` и не требует
ОС.

## 2. Что покрыто тестами

### Юнит-тесты (`tests/unit/test_core.c`)

- wrap-safe арифметика времени;
- clamp и оценки SNR/ETX;
- EWMA (сходимость);
- кольцевой буфер (push/pop/переполнение);
- таймеры (одноразовые, периодические);
- кэш дубликатов;
- кодек кадра, beacon, DAO, фрагмента (round-trip и отказ на коротком вводе);
- монотонность времени в эфире.

### Сценарные тесты (`tests/unit/test_mesh.c`)

На симуляторе:

- формирование сети (все узлы присоединяются);
- порядок Rank (строгое возрастание по цепочке);
- unicast вниз (Master → лист) и вверх (лист → Master);
- broadcast доходит до всех;
- **бесшовное перестроение**: отказ ретранслятора → узел переключается на
  другого родителя и остаётся подключён;
- **сброс интервала beacon при смене родителя** (ускоренная реконвергенция);
- **tickless-планирование** (`timer_arm`): в тишине дедлайн превышает 5 с (нет
  фиксированного тика), при передаче учитывается слот, без родителя — ограничен
  интервалом PROBE;
- **роль «лист»**: присоединяется и обменивается данными в обе стороны, не
  выбирается родителем другими узлами, не ретранслирует broadcast;
- **ACK и быстрый ремонт**: ACK принимается от любого соседа (opportunistic
  forwarding), а неотвечающий next hop помечается «подозрительным» и родитель
  перевыбирается за секунды;
- **сосуществующие сети**: две сети с разным `net_id` в одной зоне не
  обмениваются данными и не видят друг друга в таблице соседей;
- метрики соседей (RSSI/SNR/стоимость/родитель).

### Corruption-тесты (`tests/unit/test_corrupt.c`)

- CRC ловит **каждый одиночный бит** в кадре любого типа и **любое усечение**;
- неверная версия протокола и недопустимые адреса (`src=0/broadcast`, `dst=0`)
  отклоняются;
- повреждённый кадр **не создаёт состояние** (снимок соседей/маршрутов/
  родителя/Rank до и после инъекции совпадает);
- чужой `net_id` игнорируется;
- семантически битые кадры: короткий payload beacon, невозможный интервал
  beacon, DAO с `hops > MAX_HOPS`, некорректные фрагменты (`count=0`,
  `index>=count`, короткий не-последний фрагмент, разный `count`).

### Сценарий с битовыми ошибками (`test_bit_errors_tolerated`)

Симулятор вносит битовые ошибки (`sim_set_bit_error_rate`); сеть остаётся
связной, CRC отбрасывает повреждённые кадры, и ни один узел не выбирает
родителя, которого не слышит.

### Fuzzing (`tests/fuzz/fuzz_frame.c`)

Два режима в одном прогоне:

1. **Мутационный** — от корпуса валидных кадров (по одному на каждый тип +
   фрагмент) применяются случайные мутации: битфлип, случайный байт, усечение,
   перестановка. Это доходит до глубоких веток парсера, которые чистый
   случайный ввод почти не задевает (CRC их отсекает).
2. **Чисто случайные байты.**

После каждого ввода проверяются инварианты живого инстанса: размеры таблиц
соседей/маршрутов, согласованность `rank`/`connected`, отсутствие
«самородителя», корректность состояния Master. Нарушение → `abort()`.
Собирается и как обычный исполняемый файл, и с libFuzzer
(`-DTREENET_LIBFUZZER`).

### Стресс-тесты конкурентности (`tests/stress/`)

Два многопоточных теста (`make stress`, вне `ctest`):

1. **Уровень ринга** — поток-производитель и поток-потребитель прогоняют 1 млн
   записей; проверяется, что все записи целы и по порядку (нет потерянных
   обновлений индексов lock-free SPSC).
2. **Уровень библиотеки** — поток подаёт валидные BEACON-кадры через
   `treenet_rx`, поток крутит `treenet_poll`; проверяется, что число принятых
   кадров совпадает с числом обработанных (нет потерь/порчи).

### Отчёт по повторителям (`tests/sim/test_repeaters.c`)

Стресс-тест: 1 Master + 30 `REPEATER` в сетке 6×5 (шаг 150 м, дальность 250 м,
SF7). Три сценария по 180 с виртуального времени:

1. **Битые/потерянные кадры** (BER) — churn родителей по каждому узлу:
   число смен, интервалы min/avg/max, эпизоды потери связи.
2. **Пропадание питания транзитных повторителей** (в покое) — тайминги
   переподключения их прямых детей (время до ухода с отказавшего родителя).
3. **Пропадание питания при активном трафике** — дети продолжают слать
   надёжные датаграммы мастеру; измеряется время реконнекта (срабатывает
   быстрый ремонт по ACK) и «слепое окно»: сколько датаграмм отправлено,
   потеряно (`TX_FAILED`) и доставлено до переподключения.

Запуск: `make repeaters` (или `./build/treenet_repeaters`). Печатает лаконичный
отчёт и завершается с кодом 0.

## 3. Как читать результат

```
treenity tests
[core]
  test_frame_roundtrip ... ok
[mesh]
  test_seamless_reparenting ... ok

1855 checks, 0 failures
```

Ненулевой код возврата означает провал — удобно для CI.

## 4. Добавление теста

1. Напишите функцию `static void test_x(void)` и используйте `CHECK`/`CHECK_EQ`.
2. Вызовите её из `run_core_tests()` или `run_mesh_tests()` через `RUN_TEST`.

## 5. Рекомендации

- Для сценарных тестов задавайте seed — сценарии должны быть воспроизводимы.
- Задавайте топологию через `sim_set_range` и мягкую модель потерь, чтобы
  границы «слышу/не слышу» были чёткими.
- Проверяйте не только «работает», но и стабильность: число смен родителя
  (`parent_changes`) не должно расти бесконтрольно.
